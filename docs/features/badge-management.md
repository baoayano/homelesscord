# Badge management

The required FosscordBadgeManagement plugin connects the native badge directory and customization popover to the server catalog. Open User Settings, Profiles, Your badges, View Badges, then Customize Your Badges. The profile badge pencil opens the same popover. Drag any visible badge, including Staff and Nitro, or use Move to Front and Move to Back. Hide or unhide eligible badges from More options, then choose Save. Reset discards pending edits.

The free Nitro tooltip forwards the native profile badge action, including mouse clicks, Enter and Space. Badge discovery opens the viewed account's directory with Nitro selected. Own-profile customization retains the same native action as other badges. Hover and focus still show the Nitro card, and no subscription action is added.

The editor uses pointer events for mouse, touch and pen dragging. The badge shows a grab cursor, follows the pointer in a small preview, and shows an insertion line before the drop. A valid drop changes the pending order; Save persists it. Releasing outside the popover or pressing Escape cancels the drag. The grip supports Space or Enter to pick up, arrow keys, Home and End to choose a position, Enter to drop and Escape to cancel. Staff and Nitro can move like other visible badges. Reduced motion disables the short reorder animation.

While the directory is open, an existing profile popout and its frame stay rendered below the modal backdrop. Outside clicks reach the backdrop instead of the profile. The directory, its badge previews and other customization popovers remain above it. Closing the directory restores the profile's original layer without remounting it or discarding drafts.

| Route | Response |
| --- | --- |
| `GET /users/@me/badges` | Owned badges, including hidden badges, and the account's saved settings. |
| `GET /users/:user_id/badges` | Visible owned badges when viewing another account. |
| `GET /users/:user_id/badges/:badge_id` | One owned badge. A hidden badge returns 404 to other viewers. |
| `PATCH /users/@me/badges/settings` | Saved `display_order` and `hidden_badges`. |

All routes require authentication. Settings apply to the authenticated account only. Badges retain their existing profile IDs; the management catalog uses numeric ID 22 for Staff, numeric ID 1 for the evolving Nitro family, `custom:<database-id>` for other assigned badges and `pride:<flag-slug>` for selected Pride flags. Catalog entries include `legacy_id` and `profile_badge` for the client adapter. Nitro keeps the same management ID when its tier changes. Catalog artwork uses the configured instance CDN. The catalog contains owned badges and no purchase offers.

Staff can be hidden. The initial order is Staff, Nitro, then other owned badges. All visible badges can be reordered, and saved order applies to profiles. Pride remains visible, including when a stored preference has been forged to hide it. Selection continues through the existing permanent Pride picker.

Nitro can be hidden only when the server assigns treatment 1 of `2026-08-badge-management` to the account. Treatment 2, control and unknown treatments keep Nitro visible. The policy uses the existing Apex assignment resolver, including user overrides, global grants and rollout precedence. A browser-only override does not change server permission. Changing treatment to 2 makes Nitro visible on the next profile request even if its hidden preference was stored under treatment 1.

The reviewed Discord build 633029 defines this User/Apex experiment with hash 3093904580. Treatment 1 sets `enabled: true` and `tenureBadgeHideable: true`; treatment 2 sets `enabled: true` and `tenureBadgeHideable: false`. The server assigns treatment 2 and treatment 1 of `2026-05-badge-discovery-milestone-2` by default. The adapter uses server metadata for hiding and ordering and removes purchase, gifting, Boost, Quests and Orbs actions from directory details. With badge discovery enabled, a profile row shows the first 6 visible badges and a `+N` button for the rest. The directory and customization editor still list every owned badge, including selected Pride flags. The permanent Pride picker remains available independently of management treatments. When badge details open before the viewer catalog loads, the client waits for the viewer badge before reading its ID or legacy status.

Settings accept at most 512 unique owned badge IDs per array. An omitted field preserves its current eligible preferences. An empty array resets that field. Staff and Nitro IDs in `display_order` are saved and applied like other owned badge IDs. Older preferences that omit them keep Staff and Nitro in their default positions until reordered. Unknown, foreign, duplicate and protected hidden IDs return 400 before anything is saved. Numeric 1 and 22 or their string equivalents identify Nitro and Staff. Other IDs use the catalog's namespaced strings.

Updates run in a database transaction, with a PostgreSQL row lock or SQLite transaction serialization, and write only `users.badge_settings`. Concurrent partial updates preserve the other field. No-op updates avoid observer broadcasts. User updates are broadcast after a successful change. Profile responses apply preferences in both global and guild views. Public user objects do not expose private badge settings. Removed badge assignments and deselected flags cannot appear through stale preferences.

Migration `1792059984627` adds nullable JSONB settings on PostgreSQL and JSON text on SQLite. It preserves existing accounts and preferences across repeated runs. The SQLite baseline is unchanged.
